# KYLA 한국유소년라크로스협회 홈페이지

[koreayouthlacrosse.com](https://koreayouthlacrosse.com)에 올라가는 사이트 파일입니다.
`main` 브랜치에 올라온 내용이 GitHub Pages로 그대로 게시됩니다. 저장하고 몇 분 안에 사이트에 반영됩니다.

| 언어 | 주소 |
|---|---|
| 한국어 | https://koreayouthlacrosse.com/ |
| English | https://koreayouthlacrosse.com/en/ |
| 日本語 | https://koreayouthlacrosse.com/ja/ |

## 공지 올리기 (GitHub에서 직접)

1. 이 저장소에서 `assets/js/data.js` 파일을 엽니다.
2. 오른쪽 위 연필 아이콘(Edit this file)을 누릅니다.
3. `notices: [` 라고 적힌 줄을 찾아, 바로 아랫줄에 아래 덩어리를 붙여 넣고 내용을 바꿉니다.

```js
    {
      id: "2026-12-notice",
      date: "2026-12-01",
      cat: "assoc",
      title: "제목",
      summary: "목록에 보이는 한 줄 요약",
      body: [
        "첫째 문단",
        "둘째 문단"
      ]
    },
```

4. 오른쪽 위 초록색 **Commit changes** 버튼을 누르고, 뜨는 창에서 한 번 더 **Commit changes** 를 누릅니다.
5. 몇 분 뒤 사이트의 공지사항에서 확인합니다.

적을 때 지킬 것

- `id` 는 영문 소문자·숫자·하이픈(-)으로, 다른 공지와 겹치지 않게 적습니다. 공지 주소가 됩니다.
- 날짜는 `"2026-12-01"` 형식입니다. 날짜가 늦은 공지가 위에 나옵니다.
- 분류 `cat`: `event` 대회 / `edu` 교육 / `cert` 자격 / `intl` 국제교류 / `assoc` 협회
- 글자는 큰따옴표로 감싸고, 줄 끝 쉼표를 지우지 않습니다. 본문 안에 따옴표가 필요하면 작은따옴표(' ')를 씁니다.
- 본문에는 문단 말고도 `{ h: "소제목" }` 과 `{ list: ["항목 1", "항목 2"] }` 를 넣을 수 있습니다.
- 한국어로만 적으면 영어·일본어 화면에도 한국어가 그대로 나옵니다. 번역은 나중에 채워도 됩니다.

저장한 뒤 공지 목록이 통째로 사라졌다면 쉼표나 따옴표가 하나 빠진 것입니다.
파일 화면의 **History** 에서 바로 전 상태를 확인해 되돌리면 됩니다.

## 일정과 사진

- 일정은 같은 파일의 `events: [` 아래에 있습니다. 상태(`status`)를 `open` 으로 바꾸면 신청·문의 화면에 참가 신청서가 열립니다.
- 확정되지 않은 날짜, 장소, 참가비는 적지 않습니다.
- 사진은 `assets/photos/앨범이름/` 폴더에 올린 뒤(Add file → Upload files), `albums` 의 `photos` 에
  `{ src: "assets/photos/앨범이름/01.jpg", alt: "사진 설명" }` 을 추가합니다.
  긴 변 1600px 정도로 줄인 JPG가 알맞습니다. 보호자 동의를 확인한 사진만 올립니다.

  항목을 바꿀 때는 두 곳을 같은 순서로 함께 고칩니다. 휴대폰 화면 아래의 바로가기 5개는 `<nav class="tabbar">` 입니다.
- 머리줄 오른쪽, 메뉴 바로 옆의 '회원 로그인'(`.hdr__login`)은 커뮤니티 메뉴의 '회원'과 같은 곳(회원 화면, `#member`)으로 갑니다.
  휴대폰에서는 '메뉴' 단추 왼쪽에 '로그인'으로 짧게 보입니다. 머리줄에 함께 들어가도록, 좁은 화면에서는 로고 옆 단체 이름을 접습니다
  (한국어 360px 미만, 영어·일본어 420px 미만).
- 조직도는 `index.html` 의 `id="about-org"` 부분입니다. 사람이나 위원회가 바뀌면 해당 칸의 글자를 고치고,
  이름의 영문·일문 표기를 `i18n/catalog.json` 에 넣은 뒤 `python3 tools/build_i18n.py` 를 실행합니다.
  회장·부회장 표기는 바로 아래 단체 정보(`id="about-info"`)에도 있으니 함께 고칩니다. 점선 칸은 공석이라는 뜻입니다.
- 조직도로 바로 가는 주소는 https://koreayouthlacrosse.com/#about-org 입니다.
  `#화면-구역` 꼴의 주소는 그 화면을 열고 해당 구역까지 내려갑니다. 예: `#about-info`(단체 정보), `#jeju2027-form`(회신서).

## 회원 화면

| 언어 | 주소 |
|---|---|
| 한국어 | https://koreayouthlacrosse.com/#member |
| English | https://koreayouthlacrosse.com/en/#member |
| 日本語 | https://koreayouthlacrosse.com/ja/#member |

구글 계정으로 로그인합니다. 처음 로그인한 사람은 이름과 회원 종류를 적으면 바로 가입되고(승인 단계와 가입비 없음),
그다음부터는 로그인하면 아래 세 칸이 열립니다.

| 칸 | 주소 | 하는 일 |
|---|---|---|
| 내 정보 | `#member-profile` | 내 정보 보기·고치기, 자녀를 선수로 등록, 회원 탈퇴 |
| 시합 소식 | `#member-posts` | 협회가 올린 시합 일정과 안내, 사진 앨범 링크. 시합 참가 권한이 켜진 회원만 봅니다 |
| 문의하기 | `#member-inquiry` | 분류를 골라 글로 문의를 남기고, 협회의 답변을 같은 곳에서 확인 |

- **가입할 때 적는 것**: 이름, 회원 종류(선수·학부모·지도자·일반 중 하나 이상), 소속, 휴대전화. 선수는 연령 구분, 성별, 보호자 이름도 적습니다.
  이메일은 로그인한 구글 계정의 것이 그대로 들어가고 바꿀 수 없습니다. 생년월일과 집 주소는 받지 않습니다.
- **만 14세 미만**: 본인이 가입하지 않습니다. 보호자가 가입한 뒤 '내 정보'에서 자녀를 선수로 등록합니다(8명까지).
  자녀의 명부 문서에는 보호자의 계정과 연락처가 붙고, 보호자가 고치거나 지울 수 있습니다.
- **회원이 스스로 고칠 수 있는 것**: 이름, 회원 종류, 소속, 연령 구분, 성별, 보호자 이름, 휴대전화.
  상태, 시합 참가 권한, 협회 메모는 관리자 화면에서 협회만 고칩니다. 가입일은 회원이 정하지 않고, 가입한 시각(서버 시각)으로 봅니다.
- **회원에게 보이지 않게 한 것**: 회원이 만든 문서(직접 가입, 보호자 등록)는 그 회원이 읽을 수 있습니다. 화면에는 안 보여도 브라우저의
  개발자 도구로는 문서 전체가 보입니다. 그래서 협회 메모는 그 문서에 적지 않고 관리자만 읽는 `memberNotes` 에 따로 두고,
  고친 사람도 직원의 이메일이 아니라 로그인 계정의 고유 번호(uid)로 남깁니다. 문의와 시합 소식도 같습니다.
- **시합 참가 권한을 켜기 전에**: 가입할 때 적는 이름과 종류는 본인이 적은 것이고, 협회가 확인한 것이 아닙니다.
  시합 소식에는 미성년 선수의 일정과 사진 앨범 주소가 실리니, 그 계정이 실제 그 선수나 보호자인지 확인한 뒤에 켭니다.
- **시합 소식**: 로그인한 계정의 회원 문서에 시합 참가 권한이 켜져 있어야 보입니다. 관리자 화면에서 자녀에게 권한을 켜면
  보호자 계정에도 함께 켜집니다. 끌 때는 함께 꺼지지 않습니다(다른 자녀가 참가 중일 수 있습니다).
  사진은 사이트에 올리지 않고 앨범 주소(`https://` 로 시작)만 싣습니다. 보호자 동의를 확인한 사진만 넣은 앨범이어야 합니다.
- **문의**: 글만 받습니다(제목 100자, 내용 3,000자. 사진·영상·파일 없음). 분류는 회원·가입, 교육 프로그램, 대회·시합,
  지도자 자격 신청, 증빙 서류 요청, 국제교류, 후원·협력, 그 밖의 문의 여덟 가지입니다. 협회의 답변은 회원에게 그대로 보입니다.
  직원(관리자) 계정으로는 문의를 쓸 수 없습니다.
- **탈퇴**: '내 정보' 맨 아래에서 합니다. 구글 계정을 한 번 더 확인한 뒤 회원 정보, 등록한 자녀 정보, 남긴 문의, 로그인 계정을 바로 지웁니다.
  휴지통을 거치지 않습니다. 직원으로 지정된 계정은 직원 지정을 먼저 풀어야 탈퇴할 수 있습니다.
  협회가 상태를 휴면·탈퇴로 바꿔 두었거나 휴지통에 넣은 계정은 스스로 탈퇴할 수 없습니다(지우고 다시 가입해 상태를 되돌리지 못하게 하려는 것입니다).
- **계정 막기**: 가입이 열려 있어 장난 가입이나 도배가 있을 수 있습니다. 그런 계정은 지우지 말고 관리자 화면에서 상태를 '휴면'으로 바꿉니다.
  그러면 그 회원은 문의와 자녀 등록을 더 할 수 없고, 시합 소식도 보이지 않으며, 스스로 탈퇴해 다시 가입하는 것도 막힙니다.
  명부에서 완전히 지우면 같은 계정으로 다시 가입할 수 있습니다. 완전한 차단은 아닙니다. 다른 구글 계정을 새로 만들어 가입하는 것,
  기술을 아는 사람이 로그인 계정 자체를 지우고 새로 만들어 가입하는 것까지는 막지 못합니다.
- **대량으로 써 넣는 경우**: 가입과 문의는 구글 계정만 있으면 되고, 참가 의향 회신서는 로그인 없이 받습니다. 누가 일부러 대량으로 써 넣으면
  무료 사용량(하루 쓰기 2만 건)이 바닥나 그날은 저장이 되지 않을 수 있습니다. 한 계정이 등록할 수 있는 자녀 수나 문의 수를 규칙으로 세지는 못합니다.
  그런 일이 생기면 그 계정을 휴면으로 바꾸고, 반복되면 Firebase 의 App Check(자동 프로그램 차단)를 붙이는 것을 검토합니다.
- **앱 안에서 연 화면**: 카카오톡이나 인스타그램 안에서 열린 화면에서는 구글 로그인이 막힙니다. 그때는 Chrome이나 Safari로
  열라는 안내와 단추가 나옵니다.
- 회원 화면의 동작은 `assets/js/member.js` 에 있습니다. 이 파일과 구글 로그인 파일(`assets/vendor/`)은 회원 화면을 열 때만 불러옵니다.
  공지나 일정만 보는 방문자에게는 내려가지 않습니다.
- 협회가 관리자 화면에서 미리 적어 둔 명부의 사람이 나중에 직접 가입하면 명부에 줄이 하나 더 생깁니다.
  같은 사람이면 관리자 화면에서 협회가 적은 쪽을 휴지통으로 옮깁니다.

## DB와 관리자 화면 (Firebase)

회원 명부, 문의, 시합 소식, 참가 의향 회신은 협회의 Firebase 프로젝트 `kyla-homepage` 의 Cloud Firestore(서울 리전)에 저장됩니다.
로그인 계정 정보(구글 계정의 이메일과 이름)는 Firebase Authentication 에 있습니다.
관리자 화면 주소는 https://koreayouthlacrosse.com/admin/ 입니다(한국어만 있고, 검색에 나오지 않게 해 두었습니다).

| Firestore 컬렉션 | 내용 | 누가 무엇을 |
|---|---|---|
| `eoiReplies` | 2027 제주 교류전 참가 의향 회신 | 방문자는 회신서로 제출만. 관리자는 보기·추가·수정·삭제 |
| `members` | 회원 명부. 종류(`types`)는 여러 개를 함께 가질 수 있음. 협회가 적은 사람, 직접 가입한 회원(`source` = `self`, 문서 ID 가 로그인 계정의 uid), 보호자가 등록한 자녀(`source` = `guardian`) | 관리자는 보기·추가·수정·삭제. 회원은 자기 문서와 자기가 등록한 자녀 문서만 보고, 정해진 항목만 고치고, 지울 수 있음 |
| `memberNotes` | 협회만 보는 회원 메모. 문서 ID 가 회원 문서의 ID. 회원이 만든 문서(직접 가입, 보호자 등록)의 메모만 여기에 둡니다 | 관리자만 읽고 씀. 회원은 읽지도 지우지도 못함 |
| `inquiries` | 회원이 남긴 문의와 협회의 답변 | 회원(직원 제외)은 쓰기, 자기 문의 보기·지우기. 관리자는 보기, 처리 상태와 답변 적기, 삭제 |
| `matchPosts` | 시합 소식(제목, 내용, 시합 날짜, 장소, 사진 앨범 주소, 공개 여부) | 관리자가 쓰고 고침. 시합 참가 권한이 켜진 회원은 공개된 글만 봄 |
| `admins` | 관리자(직원) 명단. 문서 ID 가 구글 계정 이메일(소문자), `role` 이 `master` 또는 `admin` | 마스터만 고침. 관리자는 명단을 보기만. 누구나 자기 권한은 확인 |

관리자 화면의 메뉴는 여섯 가지입니다.

| 메뉴 | 주소 | 하는 일 |
|---|---|---|
| 대시보드 | `/admin/#home` | 주요 숫자, 확인이 필요한 일, 간단한 통계 |
| 회원 | `/admin/#members` | 명부를 표로 보기, 필터(가입 경로 포함), 통계, 추가·수정·삭제, 내려받기. 시합 참가 권한 켜고 끄기, 직원 지정(마스터) |
| 문의 | `/admin/#inquiries` | 회원이 남긴 문의 보기, 처리 상태(접수됨·확인함·답변 완료) 바꾸기, 답변 적기, 삭제, 내려받기 |
| 시합 소식 | `/admin/#posts` | 시합 참가 권한이 있는 회원에게 보일 글 올리기·고치기·삭제. 공개를 끄면 임시 저장 |
| 참가 의향 회신 | `/admin/#eoi` | 회신을 표로 보기(회신별·디비전별), 필터, 통계, 추가·수정·삭제, 내려받기. 담당자 연락처(이메일·주 연락처·전화번호)와 비고 |
| 관리자 | `/admin/#admins` | 마스터만 보임. 관리자(직원) 계정을 더하고 빼기 |

- **처음 한 번**: Firebase 콘솔 → Firestore Database → `admins` 컬렉션에 문서를 하나 만듭니다. 문서 ID 는 마스터가 될 구글 계정
  이메일(소문자), 필드는 `role` = `master`. 그 뒤로는 관리자 화면의 "관리자" 메뉴에서 더하고 뺍니다.
  관리자 이메일은 이 저장소의 어떤 파일에도 적지 않습니다. 이 저장소는 누구나 볼 수 있습니다.
- **보안 규칙**: `tools/firestore.rules` 의 내용을 Firebase 콘솔 → Firestore Database → 규칙에 통째로 붙여 넣고 게시해야
  적용됩니다. 파일만 고쳐서는 바뀌지 않습니다. 누가 무엇을 할 수 있는지는 화면이 아니라 이 규칙이 지킵니다.
- **고친 기록**: 관리자가 추가하거나 고친 문서에는 고친 시각(`updatedAt`, 서버 시각)과 고친 사람(`updatedBy`)이 남습니다.
  두 사람이 같은 문서를 동시에 고치면 나중에 저장한 쪽이 실패하고 새로 고치라는 안내가 나옵니다.
- **삭제**: 수정 창의 "휴지통으로 옮기기"는 문서에 `deletedAt` 표시만 붙입니다. 목록과 통계에서는 빠지고, 휴지통에서 되돌릴 수 있습니다.
  DB 에서 실제로 지우려면 휴지통에서 "완전히 삭제"를 누릅니다. 개인정보 삭제 요청은 여기까지 해야 끝납니다.
- **회원 종류**: 선수·학부모·지도자·직원·일반 다섯 가지이고, 한 사람이 여러 종류일 수 있습니다(예: 학부모이면서 지도자).
  문서의 `types` 에는 선수(`player`)·학부모(`parent`)·지도자(`coach`)·일반(`general`)만 적습니다.
- **직원 = 관리자**: 직원은 따로 적지 않습니다. 회원의 이메일이 `admins` 에 있으면 직원입니다. 회원 수정 창에서 직원을 켜면
  그 이메일이 `admins` 에 올라가고(끄면 빠지고), 그 구글 계정으로 관리자 화면에 들어올 수 있게 됩니다. 마스터만 할 수 있고,
  직원인 회원은 직원 표시를 먼저 풀어야 이메일을 바꾸거나 휴지통으로 옮길 수 있습니다.
- **승인 단계 없음**: 가입하면 바로 활동 회원입니다(상태는 활동·휴면·탈퇴). 시합에 참가하는 회원에게는 협회가
  '시합 참가 권한'(`matchAccess`)을 따로 켭니다. 이 권한이 있는 회원만 회원 화면에서 시합 소식을 봅니다.
- **직접 가입한 회원과 자녀**: 회원 표의 이름 아래에 가입 경로가 붙습니다. 로그인 이메일과 개인정보 동의 시각은 수정 창에 보이기만 하고
  바꿀 수 없습니다. 자녀 문서는 종류가 선수로 정해져 있고 직원으로 지정할 수 없습니다. 가입일을 비워 두면 가입한 날로 봅니다.
- **메모**: 수정 창의 메모는 협회만 봅니다. 협회가 넣은 회원의 메모는 그 회원 문서에, 회원이 만든 문서의 메모는 `memberNotes` 에 저장됩니다
  (화면에서는 똑같이 보입니다). 회원을 완전히 삭제하면 메모도 함께 지워지고, 회원이 스스로 탈퇴해 주인이 없어진 메모는
  관리자가 회원 화면을 열 때 하루가 지난 것부터 자동으로 지워집니다.
- **고친 사람 표시**: 회원이 읽을 수 있는 문서(회원이 만든 회원 문서, 문의, 시합 소식)의 '마지막 수정'에는 본인이 고쳤으면 자기 이메일,
  다른 직원이 고쳤으면 '직원', 회원이 고쳤으면 '회원 본인'이나 '보호자'로 나옵니다. 그 문서에는 이메일 대신 계정의 고유 번호만 남기 때문입니다.
- 관리자 화면은 다른 사이트의 화면 안(iframe)에 넣으면 열리지 않습니다. 주소를 직접 열어야 합니다.
- **문의의 답변**: 답변 칸에 적은 글은 문의한 회원에게 그대로 보입니다. 협회 안에서만 볼 메모 칸은 두지 않았습니다
  (회원이 자기 문의 문서를 읽을 수 있기 때문입니다). 답변을 적으면 처리 상태가 '답변 완료'로 바뀝니다.
- **시합 소식의 삭제**: 휴지통으로 옮기면 공개도 함께 꺼집니다. 되돌린 뒤 다시 공개를 켜야 회원에게 보입니다.
- **회원 명부에 넣지 않는 것**: 선수는 대부분 미성년입니다. 생년월일과 집 주소 칸은 일부러 두지 않았고, 연락처는 보호자 것을 적습니다.
- **회신의 전화번호와 비고**: 전화번호(`phone`)와 비고(`adminNote`)는 협회가 관리자 화면에서 적는 칸입니다. 회신서에는 없고, 회신자에게 보이지 않습니다.
- **회신서의 보기나 항목을 바꿀 때**: 네 곳을 함께 고칩니다. `index.html` 의 `data-key`·`data-code`·`data-div`·`maxlength`,
  `assets/js/app.js` 의 `eoiRecord`, `assets/js/admin/eoi.js` 의 이름표·수정 창·내려받기 열, `tools/firestore.rules` 의 허용 값.
  회원의 항목이나 종류·상태를 바꿀 때는 `index.html` 의 가입 양식, `assets/js/member.js`, `assets/js/admin/members.js`, 규칙을 함께 고칩니다.
  문의 분류를 바꿀 때는 `index.html` 의 `#mi-cat`, `assets/js/member.js` 의 `CATS`, `assets/js/admin/inquiries.js`, 규칙을,
  시합 소식의 항목을 바꿀 때는 `assets/js/member.js`, `assets/js/admin/posts.js`, 규칙을 함께 고칩니다.
  규칙을 먼저 게시하지 않으면 새 모양의 문서는 저장되지 않습니다.
- **규칙의 길이**: 보안 규칙은 요청 한 번에 계산할 수 있는 식의 수에 한도(1,000개)가 있습니다. 회신서는 항목이 많아
  디비전 검사를 짧게 적어 두었습니다(`validCounts`). 회신서에 항목을 더할 때는 일곱 디비전을 모두 채운 회신이 실제로 저장되는지 꼭 넣어 봅니다.
- 구글 로그인은 Firebase 콘솔 → Authentication → 설정 → 승인된 도메인에 `koreayouthlacrosse.com` 이 있어야 됩니다.
- `data.js` 의 `firebase` 설정값(apiKey 등)은 공개되어도 되는 값입니다. 서비스 계정 키(JSON 파일)와 구글 계정 비밀번호는 저장소에 올리지 않습니다.
- `assets/vendor/` 의 Firebase 파일은 관리자 화면과 회원 화면의 구글 로그인에만 씁니다. 방문자가 보는 다른 화면에서는 불러오지 않고
  (회원 화면을 열 때만 불러옵니다), 방문 통계(Analytics)도 쓰지 않습니다. `admin/index.html` 맨 위의 보안 정책(Content-Security-Policy)에는
  Firebase 프로젝트 주소가 적혀 있어, 프로젝트를 바꾸면 그 주소도 함께 바꿉니다.
- 관리자 화면은 컬렉션을 통째로 읽어 화면에서 거르고 셉니다(컬렉션마다 최대 5,000건). 무료 요금제(Spark) 한도는
  하루 읽기 5만 건, 쓰기 2만 건, 저장 1GiB 입니다. 한도를 넘거나 저장에 실패하면 회신서에는 내용을 복사해 보내 달라는 안내가 나옵니다.
- **백업**: 매일 자동으로 하려면 `tools/db-backup.gs` 를 씁니다. 협회 구글 계정의 스프레드시트에 붙여 넣으면 하루에 한 번
  모든 컬렉션을 읽어 탭마다 펼쳐 놓고, 구글 드라이브의 'KYLA DB 백업' 폴더에 날짜별 JSON 파일을 남깁니다(최근 60개).
  설치 순서는 그 파일 맨 위에 있습니다. 읽기 전용 서비스 계정의 키가 필요한데, 그 키는 스프레드시트의 스크립트 속성에만 넣고
  이 저장소에는 올리지 않습니다. 설치한 뒤나 백업이 실패했을 때는 `check` 함수를 실행하면 열쇠, 구글 인증, DB 읽기를 차례로
  확인해 막힌 곳과 까닭을 실행 로그에 적어 줍니다(아무것도 쓰지 않습니다). 손으로 받아 둘 때는 관리자 화면의 "엑셀용 파일 내려받기"를 씁니다. `=`, `+`, `-`, `@` 로 시작하는 칸은 엑셀이 수식으로
  읽지 않도록 앞에 작은따옴표(')가 붙습니다. `data.js` 의 `formEndpoint` 에 구글 시트 주소를 넣으면
  회신이 올 때마다 시트에도 사본이 쌓이고 시트 주인에게 메일이 갑니다.

## 세 언어가 만들어지는 방식

한국어가 원본입니다.

| 내용 | 한국어 | 영어·일본어 |
|---|---|---|
| 공지, 일정, 사진 | `assets/js/data.js` | 같은 파일에서 `{ ko: "…", en: "…", ja: "…" }` 로 함께 적음 |
| 화면 문구 | `index.html`, `assets/js/app.js`, `assets/js/member.js` | `i18n/catalog.json` 의 번역으로 자동 생성 |

`index.html` 이나 `app.js`, `member.js` 의 문구를 고쳤다면 번역을 맞춘 뒤 영어·일본어 페이지를 다시 만들어야 합니다.

```
python3 tools/build_i18n.py --check   # 번역이 빠진 문구 확인
python3 tools/build_i18n.py           # en/index.html, ja/index.html, assets/js/i18n.js 생성
```

`en/`, `ja/` 폴더와 `assets/js/i18n.js` 는 자동으로 만들어지는 파일이라 직접 고치지 않습니다.
`data.js` 만 고쳤을 때는 이 과정이 필요 없습니다.

## 신청서와 문의

문의는 회원 화면의 '문의하기'에서 받습니다(위 '회원 화면' 항목). 신청·문의 화면의 '문의하기' 칸은 그곳으로 가는 안내입니다.
가입하지 않은 사람에게는 인스타그램 메시지를 안내합니다.

`data.js` 의 `formEndpoint` 가 비어 있는 동안에는 대회 참가 신청서와 국제교류 문의가 전송되지 않고,
적은 내용을 복사해 인스타그램 메시지로 보내도록 안내합니다. 접수 주소를 넣으면 그 주소로 전송합니다.
참가 의향 회신서는 `formEndpoint` 와 상관없이 Firebase 에 저장되며, 접수 주소가 있으면 사본이 그쪽으로도 갑니다.

구글 스프레드시트로 받으려면 `tools/form-receiver.gs` 를 씁니다. 스프레드시트의
확장 프로그램 → Apps Script 에 붙여 넣고 웹 앱으로 배포한 뒤, 나온 주소를 `formEndpoint` 에 넣습니다.
제출될 때마다 시트에 한 줄이 쌓이고 시트 주인에게 메일이 갑니다.
